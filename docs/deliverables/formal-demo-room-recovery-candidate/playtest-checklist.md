## 启动与证据

1. 使用 Godot `4.6.3` 打开 `res://scenes/main/main.tscn`，从“开始游戏”进入，不使用选关跳过首次路线。
2. 可选开启试玩记录器时，按 `scripts/dev/room_playtest_telemetry.gd` 的公开方法记录房间进入、离开、死亡、地图打开、出口误触和能力捷径事件。
3. 自动三视角证据位于 ignored 路径 `tests/artifacts/local/room-design-recovery/final-candidate/`；重新生成命令：

```powershell
godot --path . --resolution 1280x720 -s res://scripts/dev/capture_formal_demo_room_recovery.gd
```

## 必测路线

- [ ] F01：无需外部说明完成移动、跳跃、攻击、换印和离场；失败不会掉出镜头底部才恢复。
- [ ] F02：一次房间生命周期内完成观察、首次战斗、目标确认和离场；回访不重复发奖或重锁。
- [ ] F03 → F04 → F03 → F04：第二次进入 F04 不出现“已跌落”，也不依赖隐藏深坑或越界恢复。
- [ ] F04–F05：区域方向由地标和地形建立；F05 清场后接触神龛才获得风印。
- [ ] F05–F09：能理解弹体、风印、瘴气上下路线、能力门、恢复点和三路枢纽，不靠连续文字箭头猜路。
- [ ] F09 → F10 → F08：低风险资源支路形成永久回环，返回点安全且不会连续重触发。
- [ ] F09 → F11 → F12：高风险支路可前送区域目标，失败后不产生软锁。
- [ ] F12 → F13 → F14：Air Dash 获得后立即用真实空中冲刺通过证明；失败落回安全地形。
- [ ] 回访 F06 / F07 / F09：三处旧地点分别体现奖励、永久捷径或高速线；至少 F07 为 Boss 路线所需。
- [ ] F15：回访进度清楚，缺少可选奖励不软锁；具备 F07 必要回访后可进入 F16。
- [ ] F16：地面近战、冲锋通道和空中敌层都有独立读值，清场结界与普通出口不会混淆。
- [ ] F17：入口有读招缓冲；失败后 `10–25` 秒能重新进入可操作 Boss 阶段；完成态回访不重复生成 Boss。
- [ ] F18 → F03：战后降压和返回驿站清楚；返回后不会重复授奖或错误回到 reserve 房。

## 问题记录格式

每条问题至少记录：`房间 ID / 进入来源 / 能力状态 / 位置 / 输入设备 / 现象 / 是否可复现 / 截图或遥测事件`。

- P0：崩溃、软锁、存档破坏或无法继续。
- P1：主路线不可理解、关键能力门无法证明、Boss 无法稳定重试。
- P2：视觉语义、节奏、平台舒适度或可选路线读值问题。

P0/P1 或跨房系统问题应拆成独立修复任务；普通房间局部问题回到对应 RDR-03–RDR-08 处理，不通过扩建新区域掩盖。
