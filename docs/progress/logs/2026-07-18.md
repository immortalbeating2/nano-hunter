# 2026-07-18

## 宏观银河城世界图重构

### 背景

当前 39 个可运行房间的微观构图、平台视觉和碰撞已经完成正式化，但 34 房首次通关主线在宏观上仍主要是一条阶段长链：已有支路多回到原入口，能力取得后缺少跨区域回访价值，Stage13 两条支路在出口和长期收益上也不够分离。用户要求在保留现有房量和首次通关可达性的前提下，建立至少 3 个区域环路、4–6 条远端捷径、Air Dash 回访路线、差异化 Stage13 支路和约 10–12 个锚点房。

本轮在既有 `codex/stage-17-animation-runtime-stabilization` 脏工作树上执行；Stage17 最终资产处置与 7 月 16 日平台校正均为用户已有改动，本任务不回滚、不清理、不提交或推送它们。

### 设计与计划

- 新增 `spec-design/2026-07-18-macro-metroidvania-world-graph-design.md`，冻结 3 个区域环路、SC-01 至 SC-05、两个持久探索收益和 12 组锚点职责。
- 新增根计划入口 `plan/2026-07-18-macro-metroidvania-world-graph.md`，详细清单由 `docs/implementation-plans/2026-07-18-macro-metroidvania-world-graph.md` 维护。
- 继续复用 `room_transition_requested`、`spawn_positions`、`get_hud_context()` 和 Main 跨房状态；不新增地图管理器、背包、正式存档、传送菜单或大批新房间。

### 实现

- 在 `stage9_room_base.gd` 增加通用 `ShortcutZone`、Air Dash / 探索收益门控、Main 绑定和 `NarrativeStele` 临时 HUD 提示；`stage14_backtracking_room_base.gd` 与 `stage15_boss_room.gd` 移除重复 Main 状态，复用父类契约。
- Main 增加 `collect_exploration_reward(...)`、`has_exploration_reward(...)`、`get_exploration_reward_count()`，换房和失败恢复保留，重新开始 Demo 清空；Stage13 奖励房将 `marsh_relic` / `warden_sigil` 写入该状态。
- 环路 A：Stage9 Switch 与 Stage10 Branch 建立 Air Dash + `marsh_relic` 双向远端捷径；Stage10 Aerial 与 Stage13 Entry 建立 Air Dash 双向跨区域连接。
- 环路 B：Stage13 Resource Branch 改为回到 Checkpoint，保留低压探索并授予 `marsh_relic`；Challenge Branch 增加真实瘴气危险、清场要求和 `warden_sigil`，出口前送 Goal；主路 Hub -> Return -> Goal 保持不变。
- 环路 C：Stage14 Hub 与 Stage15 Challenge 建立要求 `warden_sigil` 的双向高风险捷径；普通 Loop Return -> Pressure -> Gauntlet 路线仍保留，捷径不会跳过 Boss。
- 12 组锚点房接入训练碑、区域碑、符印机关、三路地标、秘密墙、危险机关、能力碑和封妖禁地地标；其余房间继续承担过渡、战斗节拍和呼吸。
- 新增最小 `breakable_secret_wall.gd`，复用 `receive_attack(Vector2, float)`；首版灰色网格墙在视觉复核中被拒绝，改为正式石柱切片加连续实体底层，回归直接比较可见实体与碰撞尺寸。
- 更新 Batch2 至 Batch8 生成规格中的连接、spawn 和奖励字段，避免后续重新生成正式地图时回退世界图契约。
- input-only replay 首轮在 Stage9 Switch 超时。复核确认生产薄平台仍是 one-way 薄碰撞，问题是探针连续移动导致角色未在低台站稳便跌回下层；改为复用两级上行阶段导航后，真实输入完整路线通过。生产玩家移动、跳跃参数和房间碰撞未因此改写。
