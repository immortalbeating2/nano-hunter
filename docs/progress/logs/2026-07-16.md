## 正式平台视觉 / 碰撞与跳跃可达性校正

### 背景

运行态复核发现区域 10 支路从一层跳不上二层，且教程与多个正式房间的薄平台图像顶沿和 one-way 碰撞顶沿不重合。根因不是玩家跳跃参数或 Stage17 动画，而是共享薄平台切片缺少统一纹理偏移，以及正式地图蓝图在上升一层时留下两格以上横向空档。

### 操作

- 在 `assets/art/tilesets/editor_tilesets/tutorial_thin_platform_visual_ai01.tileset.tres` 的 3 个切片上设置 `texture_origin.y=14`；当前 38 个正式房间均继续复用该资源和 `PlatformCollisionVisual.position=Vector2(0, -16)`，不改碰撞权威层。
- 通过既有 Batch 3-6 生成器收紧 Stage10 三房、Stage13 Caster / Crossfire / Pressure / Branch Hub / Challenge Branch 的上升平台间距；Stage13 Return 高台从 `y=1` 调整为 `y=2`。同时把 Pressure 房的远程敌位置移到新平台范围内。
- 在 Batch 6 生成规格补回 `stage13_goal_return`，防止后续重生成丢失 Stage14 返回落点。
- 在 `tests/demo/test_formal_map_batch3_stage10_rooms.gd` 增加共享切片顶沿断言和 Stage10 三房真实物理跳跃回归；在 `tests/stage13/test_stage_13_second_content_zone_production.gd` 增加 Stage13 空中冲刺解锁前六房上行回归。

### 验证

- 红灯基线已复现：原区域 10 支路跳跃最终落回地面；共享切片 alpha 顶沿为 `2/3/3px`，碰撞顶沿为 `16px`。
- 修复后 Stage10 `7/7` / `184` asserts，Stage13 `14/14` / `368` asserts，Batch4/5/6/7 分别 `4/4`、`4/4`、`5/5`、`4/4`；全量 GUT `33` scripts / `245/245` tests / `6207` asserts。
- `godot --headless --path . --import`、`godot --headless --path . --quit-after 3` 和 7 个变更 GDScript `--check-only` 均通过；静态蓝图审计显示 Stage9-13 所有上升台阶净空均为 `64px`，`bad=[]`。
- Windows 运行态 capture：Stage10、Tutorial、Stage13 Batch4/5/6 报告全部 `ok=true`；代表性截图确认角色脚底与平台视觉顶沿一致。MCP bridge 监听存在但当前编辑器未完成 workspace handshake，本轮未杀进程或清理既有 `project.godot` MCP autoload，改用仓库 capture 脚本完成运行态取证。
