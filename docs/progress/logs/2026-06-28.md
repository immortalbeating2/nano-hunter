## DemoShell 开始界面与开始入口修复

### 背景

用户反馈当前游戏开始界面标题、按钮和面板排列不整齐，并且点击“开始”后只剩标题背景，没有真正进入可见游戏画面。复核 `DemoShell` 后确认主因是全屏 `TitleBackground` 位于 DemoShell 根节点下，开始按钮只隐藏 `MainMenu`，没有隐藏标题背景，因此游戏已经重开但被标题背景覆盖。

### 操作

- 修改 `scripts/ui/demo_shell.gd`：主菜单打开时显示 `TitleBackground`，开始、暂停和重开进入运行态时隐藏它。
- 修改 `scenes/ui/demo_shell.tscn`：加宽主菜单面板，调整标题、状态文案、开始按钮和装饰图的位置，降低标题字号，避免 640x360 基准视口下溢出。
- 扩展 `tests/stage16/test_stage_16_alpha_demo_candidate.gd`：新增回归测试，保护开始后 `TitleBackground` 和 `MainMenu` 必须隐藏，且仍回到教程房间。
- 新增 `scripts/dev/capture_demo_shell_start_review.gd`：保存主菜单态和开始后运行态截图，并输出 JSON 报告。

### 验证

- `godot --headless --path . -s addons/gut/gut_cmdln.gd -gtest=res://tests/stage16/test_stage_16_alpha_demo_candidate.gd -gexit`：通过，`14/14 passed`、`137` asserts。
- `godot --rendering-driver opengl3 --path . --script res://scripts/dev/capture_demo_shell_start_review.gd`：通过，生成：
  - `tests/artifacts/local/demo-shell-start-review/demo_shell_menu.png`
  - `tests/artifacts/local/demo-shell-start-review/demo_shell_started.png`
  - `tests/artifacts/local/demo-shell-start-review/demo_shell_start_review_report.json`
- `git diff --check`：通过，仅保留既有 JSON / MD CRLF warning。

### 结果

开始界面现在在主菜单态显示标题背景和更宽的居中面板；点击“开始”后标题背景与主菜单都会隐藏，玩家实例存在，游戏画面不再被标题背景遮住。

### 风险 / 遗留

- 本轮只修复当前 DemoShell 首屏布局和开始入口遮挡，不处理完整发布级 UI 字体、按钮状态、动效或最终视觉签核。

## 教程玩家占位叠层与第一跳可达性修复

### 背景

用户反馈运行态玩家仍显示蓝色占位块、黄色头标等旧占位资产，和正式生成的 Luna 角色动画重叠；同时教程第一跳平台实际跳不上去，平台如果调得过低又会失去“跳台”意义。复核后确认玩家场景中 `Body`、`Stage12Silhouette`、`Stage12HelmetMark`、`Stage12AssetSprite`、`LunaReadabilityArt` 和正式 `LunaRuntimeAnimationVisual` 同时可见。教程平台需要保持头顶平台语义：下方可通行、上方需跳跃、跳跃可实际到达。当前 `jump_velocity = -340` 对这个语义偏保守，不能稳定覆盖首个教学平台。

### 操作

- 修改 `scenes/player/player_placeholder.tscn`：隐藏旧 `Body` / Stage12 / readability 视觉层，保留节点、metadata、资源引用和 `CollisionShape2D`，正式运行态继续显示 `LunaRuntimeAnimationVisual`。
- 修改玩家跳跃配置：将 `jump_velocity` 从 `-340.0` 调整为 `-420.0`，保留现有重力、可变跳高和碰撞尺寸。
- 修改 `scenes/rooms/tutorial_room.tscn`：将 `JumpGuidePlatform` 调整为 `Vector2(-144, 84)`，平台底部高于玩家头顶，可从下方通过；顶部仍高于地面，需要跳跃到达。
- 修改 `assets/configs/rooms/tutorial_room_flow.tres`：将 `move_jump_goal_y` 调整为 `64.0`，确保玩家站上平台后教程能推进，同时站在地面不会误触发。
- 恢复 `project.godot` 显示契约：`640x360` 基准 viewport、`1280x720` 窗口、`viewport / keep / integer` 缩放，避免把 UI 和房间按 1280 基准直接渲染导致尺寸不适。
- 扩展 Stage5 GUT：新增平台高度与玩家跳跃参数匹配检查，新增真实物理跳跃回归，并新增平台下方通行回归。
- 扩展 Stage14 GUT：保护旧玩家占位视觉层默认隐藏，正式 `LunaRuntimeAnimationVisual` 可见且播放。

### 验证

- `godot --headless --path . -s addons/gut/gut_cmdln.gd -gtest=res://tests/stage1/test_stage_1_startup_skeleton.gd -gexit`：通过，确认显示缩放契约恢复。
- `godot --headless --path . -s addons/gut/gut_cmdln.gd -gtest=res://tests/stage2/test_stage_2_movement_feel.gd -gexit`：通过，确认基础跳跃状态、可变跳高、coyote time 和 jump buffer 未被破坏。
- `godot --headless --path . -s addons/gut/gut_cmdln.gd -gtest=res://tests/stage5/test_stage_5_tutorial_vertical_slice.gd -gexit`：通过，覆盖真实跳跃上平台和平台下方通行。
- `godot --headless --path . -s addons/gut/gut_cmdln.gd -gtest=res://tests/stage12/test_stage_12_asset_pipeline_and_demo_polish.gd -gexit`：通过，`9/9 passed`、`152` asserts。
- `godot --headless --path . -s addons/gut/gut_cmdln.gd -gtest=res://tests/stage14/test_stage_14_backtracking_and_ability_gating.gd -gexit`：通过，`15/15 passed`、`279` asserts。
- `godot --rendering-driver opengl3 --path . --script res://scripts/dev/capture_demo_shell_start_review.gd`：通过，刷新 `tests/artifacts/local/demo-shell-start-review/demo_shell_started.png`，运行态不再显示旧蓝色身体块和黄色头标。

### 结果

正式运行态玩家不再叠加旧占位资产；教程第一跳平台现在保留头顶平台意义，既能从下方通过，也能实际跳上，并且教程步骤会在站上平台后推进到 dash 教程。项目显示缩放恢复到 Stage1 基准契约，避免用户重设窗口后进入游戏比例不适。

## 教程攻击红柱解锁与 HUD 紧凑化复核修正

### 背景

用户继续反馈教程 3/4 中间红色柱子无法跳过，攻击也不起效果；同时教程提示与状态 HUD 的文字和框没有对齐，字号和面板过大，占据大量游戏视觉空间。复核后确认红柱是 `ExitBarrier` 静态碰撞门，原流程只允许攻击 `TutorialDummy` 解锁出口；但从玩家视角看，红柱就是最显眼的阻挡目标，攻击它没有反馈会造成错误门控表达。HUD 方面，`PromptPanel` 和 `BattlePanel` 直接使用正式九宫格皮肤，但运行态字号和文案长度过大，文字贴近装饰边缘。

### 操作

- 新增 `scripts/rooms/tutorial_exit_barrier.gd`：让 `ExitBarrier` 支持 `receive_attack(...)`，并发出 `hit_registered` 信号。
- 修改 `scenes/rooms/tutorial_room.tscn`：给 `ExitBarrier` 挂接教程封印柱脚本。
- 修改 `scripts/rooms/tutorial_room.gd`：教程攻击步骤中，命中训练假人或红色封印柱都能调用同一套出口解锁流程；其他步骤命中红柱不提前跳流程。
- 修改 `assets/configs/rooms/tutorial_room_flow.tres` 和脚本 fallback 文案：把攻击提示改成“J 攻击训练目标或红色封印柱，打开出口。”，并缩短移动、dash、出口提示。
- 修改 `scenes/ui/tutorial_hud.tscn`：缩小左右 HUD 面板，降低字号，把文字区下移到九宫格装饰安全区内；隐藏候选资源引用节点保持不变。
- 扩展 `tests/stage5/test_stage_5_tutorial_vertical_slice.gd`：新增红色封印柱攻击解锁回归，并保留此前真实跳跃和平台通行回归。

### 验证

- `godot --headless --path . -s addons/gut/gut_cmdln.gd -gtest=res://tests/stage5/test_stage_5_tutorial_vertical_slice.gd -gexit`：通过，`8/8 passed`、`56` asserts。
- `godot --headless --path . -s addons/gut/gut_cmdln.gd -gtest=res://tests/stage12/test_stage_12_asset_pipeline_and_demo_polish.gd -gtest=res://tests/stage16/test_stage_16_alpha_demo_candidate.gd -gexit`：通过，`23/23 passed`、`289` asserts。
- Godot MCP Pro 运行态复核：
  - `play_scene main` 后通过 `click_button_by_text("开始")` 进入游戏。
  - 保存截图到 `tests/artifacts/local/tutorial-gate-ui-review/`：
    - `01_started_compact_hud.png`
    - `02_attack_step_before_barrier_hit.png`
    - `03_after_player_attack_barrier_open.png`
  - 通过 `set_game_node_property` 推进到教程攻击步骤，把玩家放到红柱左侧后发送真实 `simulate_action("attack")`。
  - 运行态读值返回：`step=exit; unlocked=true; barrier_collision_disabled=true; barrier_hit_count=1`。

### 结果

教程 3/4 不再要求玩家猜测只能打训练假人；攻击训练假人或攻击红色封印柱都会打开出口。红柱仍保持阻挡门语义，不需要通过跳跃翻越。HUD 现在保留正式九宫格皮肤，但提示文案更短、字号更小，文字位于安全区内，不再像此前那样占据半屏或明显压框。

### 风险 / 遗留

- 本轮不改变玩家攻击时序、hitbox 大小、伤害数值、恢复充能或房间跳转契约。
- 本轮是当前教程 HUD 的明显问题修正，不等于最终发布级 HUD 重设计；后续仍需要统一 typography、图标语义、正式状态面板和 UI 动效。
