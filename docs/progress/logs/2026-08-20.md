# 2026-08-20 开发日志

## F09 单向平台下穿与 F10 自然入口修复

### 判断与根因

- 用户截图中的 Luna 头部与上方平台持续重叠，不属于“平台能否跳上”的同一问题。类银河恶魔城允许角色穿越单向平台时短暂前景遮挡，但正常站立时视觉轮廓持续切入平台会削弱空间可读性；当前净空测试只按 `40u` 碰撞体，不覆盖 Luna 正式视觉轮廓，因此该项作为独立视觉净空缺陷保持开放。
- F09 上层路线实际通过两个 `64u` 中继跳跃可达；真正阻断 F10 的是中层 `one_way_rect` 覆盖下层资源入口，而 Player 没有读取 `ui_down` 或执行下穿。
- 旧 F09→F10→F08 测试直接把玩家放到 `ResourceBranchZone`，只能证明触发器和切房信号有效，不能证明玩家可以自然抵达。

### 修正

- `FormalRoomGrayboxLayout` 只给运行时单向平台加入 `one_way_platform` 分组，实体地面不加入。
- Player 在脚下碰撞体属于该分组、同时按住下方向并按跳跃时，越过 `8u` one-way 容差并进入向下速度；普通跳跃、实体地面、Dash 和 Air Dash 顺序不变。
- F09 HUD 增加“下层资源支路：按住下方向并跳跃，穿过单向平台”，主菜单控制说明同步显示当前 InputMap 的下方向与跳跃绑定。
- 正式回环测试改为真实输入，不再传送到 F10 入口。

### 验证与边界

- TDD RED：玩家稳定站在中层 `y=171.99`，按下+跳后仍回到 `y=171.98`，F09→F10 信号为 `0`；直接传送到下层入口仍能切房，确认触发器不是根因。
- GREEN：同一真实输入落到 `y=267.98`，唯一发出 F09→F10；上层两个完整 `64u` 跳跃仍可达。
- 新鲜 GUT：房间设计 `48/48 / 956`、Stage2 `7/7 / 42`、Stage13 `15/15 / 390`、Stage14 `16/16 / 271`、Stage16 `22/22 / 645`。
- Windows/OpenGL 真实 Main 通过正式选关进入 F09，运行 HUD 显示下穿提示，组合键后当前房变为 F10，报告 `ok=true`；证据位于 ignored 的 `tests/artifacts/local/f09-drop-through-review/`。
- 递归 GUT 为 `424/428`：本次相关测试均通过；剩余 4 个失败分别是旧普通房 `Floor` 边缘假设、既有 SC-06 门控断言，以及正式 F 编号上线后尚未同步的 Stage21 提示文案期望。Stage20 单独复跑仍为 `5/6`，确认不是本次下穿状态串扰；本轮不越界修改这些既有失败。
