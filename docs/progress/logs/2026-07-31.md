# 2026-07-31 开发日志

## Stage26 主菜单 / 暂停菜单手柄导航修复

### 背景

用户使用已连接的 Xbox Series X Controller 复核候选版时，确认主菜单和暂停菜单无法使用手柄操作。此前实体复核只证明真实按键、摇杆、漂移与游戏内生产动作，没有覆盖 UI 初始焦点与确认 / 返回链，因此不能用旧证据否定本次反馈。

### 根因

- 主菜单与暂停菜单显示时没有调用 `grab_focus()`，干净启动后的 GUI focus owner 为 `none`。
- Godot 内建 `ui_accept` / `ui_cancel` 只有键盘事件，`ui_up/down/left/right` 也没有生产手柄映射；真实 A / B、左摇杆与十字键无法驱动 Control。
- 直接把 B 加到 `ui_cancel` 后会与游戏内 Dash 共用同一物理键；旧 `_unhandled_input` 会把游戏中的 B 当成暂停入口，形成新冲突。

### 操作

- 在 `project.godot` 显式补齐六个 UI 动作：左摇杆 / 十字键导航、A 确认、B 返回，同时保留原方向键、Enter / KP Enter / Space 与 Esc。
- `DemoShell` 在主菜单、详情页、详情返回和暂停菜单入口恢复确定焦点。
- 收紧 `_unhandled_input`：Menu / Esc 可从游戏中打开暂停；B / `ui_cancel` 只在地图、详情或已打开的暂停菜单内返回，游戏中 B 仍只负责 Dash。
- Stage26 新增真实 `InputEventJoypadButton` 菜单链回归，覆盖主菜单导航、A 打开详情、B 返回、A 开始、B 不误开暂停、Menu 暂停、暂停菜单导航、A 打开地图与 B 返回。

### 红绿证据

- 修复前 Stage26 为 `5/6`；新菜单用例在 InputMap、主菜单焦点、导航、确认、暂停焦点与地图返回共出现 `13` 处失败。
- 加入 A / B 后先新增 Dash 冲突断言，确认游戏中 B 会错误打开暂停；收紧输入边界后回归转绿。
- 最终 Stage26：`6/6` tests、`78` assertions。

### 运行态复核

- Godot MCP Pro 直连当前工作树，识别实体 Xbox 手柄为设备 `0`。
- 干净主菜单 focus owner 为 StartButton，方向输入可移动到 ContinueButton。
- 进入暂停后 PauseMenu 可见、场景树暂停且 focus owner 为 ResumeButton。
- 生产运行态将原始 B Joypad 事件交给 DemoShell 时 `paused=false`、PauseMenu 不显示，确认 Dash / 返回冲突已隔离。
- MCP 输入辅助在暂停树内存在工具传输不稳定，因此完整 A / B / Menu 菜单链以同一生产场景的 GUT 原始 Joypad 事件作为确定性证据；未把 MCP 断连伪报为产品崩溃。

### 最终验证

- `godot --headless --path . --import`：通过；只保留 ignored 本地资产证据副本的 `6` 条重复 UID warning。
- Stage16 / 19 / 21 / 22 / 23 / 24 / 25 / 26 邻近组合：`8` scripts、`57/57` tests、`1020` assertions。
- 递归全量 GUT：`42` scripts、`300/300` tests、`8540` assertions；只保留既有 orphan / ObjectDB 退出期 warning。
- `godot --headless --path . --quit-after 3`：通过。
- 一次性 InputMap 写入脚本已删除，本轮自有 nano-hunter 编辑器已关闭，临时 MCP autoload 零残留。

### 风险 / 遗留

- 功能性手柄菜单链已纳入自动与 MCP 复核，不再依赖人工才能发现完全不可操作的问题。
- 真人首次通关、能力回访、悬赏 / Build 理解度以及按键舒适度、误按和菜单节奏仍属于外部人工签核。

## 全生产房间可踩面视觉 / 碰撞对齐修复

### 背景与根因

- 用户反馈教程台阶等资产与碰撞层仍大量错位。运行态测量确认 Luna 自身碰撞底边与角色图片脚底只差约 `0.23px`，问题来自地形。
- 2026-07-16 的共享校正测试按 `alpha_top + texture_origin.y` 计算可见顶沿，但 Godot 的正向 `texture_origin.y` 实际把图片向上移动，正确关系是 `alpha_top - texture_origin.y`；错误的 `texture_origin.y=14` 因共享 TileSet 扩散到 38 个正式 TileMap 房间，造成薄平台可见顶沿与 one-way 碰撞顶沿相差 `27-28px`。
- 38 个房间的 `TerrainCollisionVisual` 与 `PlatformCollisionVisual` 同时承担碰撞并以 `8%` 透明度绘制，形成第二套幽灵地形；地面左右 cap 图片自身 alpha 顶沿另有 `1-2px` 差异。

### 修改

- 将薄平台 left / center / right 的共享原点改为 `-14/-13/-13`，地面 left / center / right 改为 `+1/0/-2`。
- 38 个正式房间隐藏 `TerrainCollisionVisual` 与 `PlatformCollisionVisual`，保留其碰撞；独立 surface 层继续只负责显示。
- 同步 12 个正式地图生成脚本，后续重建不会重新显示碰撞权威层。
- 修正旧 Stage10 共享切片测试的方向，并新增 `test_walkable_surface_visual_collision_alignment.gd`：从生产世界图配置审计全部 44 房、真实纹理 alpha 边缘、碰撞多边形、图层权威与退役碰撞状态。
- 教程与 Stage14 运行态截图脚本增加“碰撞层隐藏、碰撞仍启用”的门禁。

### 验证

- 红灯基线：38 个正式 TileMap 房间均报告薄平台 `27-28px` 错位和碰撞层可见；6 个 Stage25 静态 Floor 房间无错位。
- 全房间审计：`1/1` test、`4` assertions；Stage10 共享平台与真实跳跃：`7/7` tests、`184` assertions。
- Tutorial / Stage14 / Stage15 模板：`16/16` tests、`1358` assertions；Stage5/9/10/13/14/15/16/25 相邻组合：`97/97` tests、`1864` assertions。
- 递归全量 GUT：`43` scripts、`301/301` tests、`8542` assertions。
- Godot `4.6.3` import 与主场景 smoke 通过；import 仅保留既有 ignored 证据重复 UID 和退出期 ObjectDB 警告。
- Windows/OpenGL 教程报告与 Stage14 gate 报告均为 `ok=true`；教程前后截图确认 Luna 脚底从平台底缘回到可见顶缘，Stage14 普通跳回退、Air Dash 落点和门区安全面通过真实物理演练。
- `project.godot` 的 MCP 临时 autoload 已清理，既有输入映射改动保持不动。

### 风险 / 遗留

- 当前 44 个生产房间已纳入自动审计；未来若正式接入 `stair_ramp` 或坡道，需要扩展同一测试以覆盖斜边，而不是复用水平顶沿判定。
- 本轮未更换美术、重排房间或调整玩家碰撞体，避免把对齐修复扩大为关卡重制。
