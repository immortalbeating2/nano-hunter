# 正式 Demo Blueprint V2 运行时落地设计

## 文档定位

本设计承接 `2026-08-26-formal-demo-room-blueprint-v2-design.md`，把 F01–F18 从“完整玩法蓝图候选”推进到可运行灰盒。它不改变方案 B、18 房身份、正式拓扑或现有 `room_transition_requested` 架构，也不提前进入正式美术生产。

运行时事实源仍是生产 `.tscn`、现有房间脚本和 `assets/configs/world_map/formal_demo_room_program.json`。Blueprint V2 是施工合同，不作为运行时 JSON 依赖。

## 决策

采用最小复用方案：

1. 结构继续使用现有 `FormalRoomGrayboxLayout`；已有专用几何能满足 V2 时保留，不为统一节点名而重做。
2. 普通相邻边界和单向地形允许自动切房；建筑门、祭坛、法坛和需明确选择的支路统一使用既有 `ui_down` 确认，不新增全局交互键或交互管理器。
3. 门控、checkpoint、奖励和持久状态继续由现有房间 signal、Main 字段和 Player 能力接口管理，不新增 SaveManager 或第二套状态机。
4. 正式美术延后。保留不误导路线的现有背景、地表和已接入物件；隐藏无语义旧门、调试箭头和碰撞色块；缺失语义使用可辨认的程序化或现有通用代理物。
5. 自动路线必须通过生产 Main 和真实 Player 输入完成。允许 runner 在用例开始前选择房间和状态，但路线执行期间不得调用切房函数或改玩家坐标。

## 灰盒对象合同

- 背景：只承担远景和气氛，不推断碰撞。
- 实体地形：由 `FormalRoomGrayboxLayout.solid_rects` 或现有独立 StaticBody2D 表达。
- 单向平台：由 `one_way_rects` 或等价显式平台表达，并验证 `ui_down` 下穿。
- 出口：必须有独立 Zone/Marker、目标 Spawn、到达支撑和防反弹空间。
- 交互代理：必须与对应碰撞/Zone 对齐；代理物可临时，交互语义不可临时。
- 危险：必须有可见预读、安全回落或近点重试，不以 Main 越界死亡替代房间恢复。
- 相机：每段覆盖主要地面、出口/危险预读和角色头顶净空；不能让可走地面长期落出视野。

## 交互映射

| V2 类型 | 运行时动作 | 复用实现 |
| --- | --- | --- |
| `adjacent_boundary` | `cross` | 现有 ExitZone/LeftExitZone 自动切房 |
| `one_way_terrain` | `fall_or_slide` | 单向平台/滑道，自动切房 |
| `architectural_door` | `ui_down` 确认 | 现有 Zone + `_transition_requested` + signal |
| `remote_waystation` | `ui_down` 确认 | Marker/Zone + 距离 + signal |
| `ability_gate` | 指定能力动作 | 现有 GateBarrier、Player 能力和证明传感器 |
| `encounter_gate` | 清场 | 现有 enemy `defeated` → `unlock_gate()` |
| `boss_gate` | 条件满足后 `ui_down` | 现有 Boss barrier/胜利状态 |

确认使用边沿输入，避免按住按键跨房连续触发。切房仍只能由房间发 `room_transition_requested`，房间不得直接调用 Main。

## 代理资产策略

- F02 悬令台：复用 F03 的悬赏板图形语言与独立 Zone；只标记为灰盒代理。
- F07/F14 祭坛：复用现有 `ShortcutMarkerArt`/封印桩语言，位置必须与普通出口分开。
- F10：保留现有 `SecretWall` 和奖励拾取图；补纯视觉遗物龛/滑道代理。
- F18：复用现有 waystation 图形语言建立独立法坛；不把普通 ExitZone 或装饰门冒充法坛。
- 能力门/Boss 门：继续复用现有 GateBarrier 组件；普通户外出口不摆无意义实体门。

## 自动验收层级

### A. 静态生产采纳

- F01–F18 正式 scene 路径与 room program 一致。
- 每房段数、相机边界、Spawn、支撑地形、必需交互节点和连接语义可机器审计。
- 所有 Spawn 位于支撑面上且落点离源触发器足够远。

### B. 房间行为

- 锁定状态不切房；成功状态只切一次。
- 主动交互必须等待 `ui_down` 的新按下。
- 奖励、能力、checkpoint 和清场状态重复进入不重复发放。
- 跌落/失败回到安全层或近点重试，不出现假坠落弹窗。

### C. 自然输入路线

- 18/18 房至少一条生产主路线用真实 Player 输入通过。
- 所有关键双向/支路连接覆盖：F07↔F14、F09→F10→F08、F09↔F12、F14→F15、F18→F03。
- 路线运行期间禁止直接 `transition_to_room()`、禁止改玩家坐标；测试初始化可选择起始房和批准状态。
- 每条路线记录耗时、进入/离开房、目标 Spawn、死亡/跌落、误触和反弹。

### D. 运行态视觉

- 每房至少捕获入口/核心/出口；多状态房补锁定/开放或首次/回访图。
- 地面、危险、交互对象、主出口和支路在 3–5 秒内可辨。
- 程序化代理物可以不精美，但不能呈现错误门型、错误路径或碰撞色块。

机器、运行态和视觉内部复核全部通过，才能称“18 房灰盒候选完成”。真人手感确认和正式美术仍是后续独立门禁。

## 非目标

- 不重写 Main 切房、InputMap、Player 状态机或存档架构。
- 不让运行时读取设计目录中的 Blueprint JSON。
- 不生成正式背景、地形套件、门、祭坛或音频资产。
- 不清理当前工作树、分支、worktree，不 commit、merge、push 或发布。
