# Stage19 房间蓝图与探索地图设计

## 文档定位

Stage19 把已经存在的房间内容目录、正式场景几何和 Stage18 世界图连接收成一套玩家可理解的房间蓝图。它不重新生成 38 房，也不把空房一律塞入敌人；优先解决两个会直接放大“一本道”感受的 P1 缺口：世界图不可见，以及 Stage11 仍保留旧 Demo 终点 / 重开语义。

本阶段继续偏离“先实现元素 + 姿态切片”的推荐顺序，原因是用户明确批准按房间设计缺口推进。偏离范围只包含探索地图、已发现房间状态和 Stage11 连接语义；完成后仍回到北极星战斗切片。

## 事实来源与房间蓝图契约

Stage19 不复制一套会漂移的像素坐标目录，组合以下真源：

1. `.tscn`：平台、碰撞、敌人、危险、出生点和出入口坐标的唯一真源。
2. `spec-design/2026-07-28-alpha-demo-room-blueprint-matrix.md`：38 房职责 / 平台、出入口、敌人、陷阱、门控、奖励和叙事的逐房核对结果。
3. `spec-design/2026-07-11-alpha-demo-room-content-catalog.md`：敌人、机关、奖励和房间职责统计。
4. `spec-design/2026-07-25-alpha-demo-world-map-blueprint.md`：34 房首次路线、4 个可选房、3 个区域环路和 5 条远端连接。

每个正式房间必须能由这些真源共同回答八个问题：主要职责、入口安全区、出口方向、平台 / 高度节拍、敌人与危险、门控 / 机关、奖励 / 叙事、首次经过与回访价值。矩阵中的 `—` 是明确留白，不表示必须新增内容；连接房、恢复房和战后降压房允许以“无敌人”作为节奏职责。

## 逻辑世界坐标

当前游戏采用离散切房，没有连续世界坐标。Stage19 地图只保存 `0..1` 归一化 UI 坐标，不改变房间场景自身坐标、Camera Limits 或碰撞。

- `assets/configs/world_map/alpha_demo_world_map.json` 是房间编号、标题、区域、相对位置和展示连接的唯一地图布局配置。
- 五个区域以松散星座而非五行蛇形排布；34 房安全首次路线仍与实装一致，但视觉上用高低回环、支路和长捷径表现真实非线性关系。
- 可选 A 位于 07 / 09 回环；B、C 位于 Stage13 分流；D 位于 Stage14–15 高风险回路。
- 后续新增、移动或改连房间只改该 JSON 与对应测试；不重新生成地图底图，也不修改 `WorldMapView` 绘制器。
- 归一化位置只表达区域归属和相对关系，不假装代表连续世界米制距离。

## 发现式地图

### 玩家状态

Main 在当前一轮 Demo 内记录已进入房间路径，并提供只读地图快照：

- `current_room_path`
- `visited_room_paths`
- `air_dash_unlocked`
- `marsh_relic_collected`
- `warden_sigil_collected`

重新开始 Demo 或测试选关会清空发现状态，再把起始房记为已发现。换房和失败重载不会丢失本轮发现记录；本阶段不写正式存档。

### 地图读值

- 已发现房间：按区域色显示小型佛龛 / 符印节点，不再使用调试矩形。
- 当前房间：古金实体符印、青白外环和编号高亮。
- 与已发现房相邻但未进入的房间：只显示墨雾中的空心符印，不泄露完整区域。
- 普通主路 / 支路：使用弧形墨线；支路用玉色区分，未完全发现时降低亮度。
- 远端连接：使用金色断续弧线；条件未满足时保持低亮，满足后提高亮度。
- 地图从暂停菜单进入，继续复用 DemoShell 的暂停所有权；本阶段不增加第二套暂停或输入状态机。

### 美术层分离

- `stage19_discovery_map_base_ai01.png` 只包含宣纸、黑漆铜框、莲纹和无语义山水气氛；不得包含文字、房间、路线、图标或门控。
- `spec-design/images/2026-07-28-stage19-discovery-map-visual-reference.png` 是组件语言母版，只供对照，不得被任何运行时场景引用。
- `WorldMapView` 在底板上动态绘制区域名、曲线路径、符印节点、相邻墨雾和发现状态。
- DemoShell 保持底板原始宽高比，并按视口扩展到最大 `1600x1100`；2K 运行态不再使用旧 `900x620` 小窗。
- 生图只在外框 / 纸张美术方向整体变更时重做；普通路线和房间调整不触发生图。

### 数据边界

地图视图从独立 JSON 读取逻辑坐标和展示连接，但场景导出字段仍是实际切房权威。Stage19 测试必须比较两者，防止地图画出不存在的路线。地图是 UI，不作为碰撞、生成、快速旅行或房间加载来源。

## Stage11 镇妖驿厅化

现有 `stage11_demo_end_room` 路径和节点名为历史稳定句柄，Stage19 不重命名文件，避免扩大引用改动；只修正玩家语义和连接行为。

- 中央 Goal marker 改为“驿厅封印回响确认”，仍负责本房 checkpoint 和 HUD 状态推进。
- 左侧旧 Replay 入口改为返回 Stage10 Challenge 的右侧安全出生点。
- 右侧 Continue 入口继续进入 Stage13 Entry。
- Main 新增 `short_chain_completed` 兼容历史 Stage11 自动化，但 `demo_completed` 只在 Stage16 Alpha Demo End 置真。
- HUD 不再在 Stage11 显示“Demo 已完成 / 重开试玩”，改为“镇妖驿厅 / 左返试炼 / 右入瘴泽”。

## 房间内容决策

- 保留 16 个战斗房、24 个普通敌人和 1 个 Boss 的当前数量；本阶段没有证据支持加怪。
- 保留 Stage14 / Stage16 无普通敌人的机关与回收节奏，它们不是自动缺口。
- 保留三类样板和 Batch 1–9 已验证的平台、敌人位置、门前后安全区。
- Stage19 只触达 Stage11 行为、Main 探索状态、DemoShell 地图入口和地图视图；其余 37 房不改运行时几何。

## 验收口径

1. 地图布局覆盖 38 个正式房间，排除 `test_room`。
2. 34 房首次路线和四个可选房均有稳定编号；SC-01 至 SC-05 与 Stage18 场景连接一致；布局不退回五行蛇形。
3. 首次进入只发现当前房与相邻轮廓；切房后已发现集合递增，重开后重置为 Tutorial。
4. Air Dash、`marsh_relic`、`warden_sigil` 会改变对应捷径的地图亮度，不改变实际门控权威。
5. 暂停菜单能打开地图、返回暂停菜单并继续游戏，不叠加主菜单 / 详情页。
6. Stage11 左侧返回 Stage10 Challenge，右侧进入 Stage13 Entry；Stage11 只完成短链，Stage16 才完成 Alpha Demo。
7. 地图底板与拓扑配置相互独立，视觉母版无运行时引用；房间移动只需修改 JSON。
8. Stage19 GUT、受影响 Stage11 / 13 / 16 GUT、全量 GUT、Godot import、主场景 smoke 和地图运行态截图取得新鲜证据。

## 非目标

- 不新增房间、敌人、陷阱、能力、装备、货币或剧情对话系统。
- 不实现正式存档、快速旅行、地图缩放 / 拖拽、全屏战争迷雾 shader 或直接地图快捷键。
- 不让地图配置驱动真实切房，不重写 `room_transition_requested`。
- 不用生成图片替代 Godot 场景中的平台、碰撞、危险和出入口数据。
