# Stage21 元素、姿态与两步序列设计

## 目标

让现有攻击第一次形成 Nano Hunter 的 30 秒核心循环：切换元素与符印姿态，连续释放两次攻击，按元素顺序得到不同的可读收益。Stage21 只验证 `wind` / `thunder`、`swift` / `ward` 和两步序列，不扩完整元素池、技能树或新招式。

## 玩家循环

1. `Q` 在已开放元素间切换；雷默认可用，Stage10 风印开放风元素并自动切到风。
2. `E` 在疾印与御印间切换；切换冷却为 `0.35s`。
3. 每次攻击起手记录当前元素，序列只保留最近两步，窗口为 `2.0s`。
4. 第二步形成反应时，本次攻击立即获得对应形态：
   - `wind -> thunder`：追击贯穿，攻击横向判定增加 `24px`。
   - `thunder -> wind`：散射破势，攻击纵向判定增加 `16px`，击退倍率为 `1.75`。
5. 御印让普通攻击纵向判定增加 `8px`、击退倍率为 `1.15`；疾印保留 Stage20 原攻击基线。

## 状态边界

- Main 持有当前元素与姿态，玩家切换后通过信号回写，换房时注入新玩家。
- Player 持有两步序列、窗口计时和当前攻击反应；换房、失败重生都会因玩家重建而清空。
- 重开 Demo 将元素恢复为雷、姿态恢复为疾，并清空序列。
- 风印只有在当前元素为风时允许普通攻击查询并斩散敌方弹体。
- Main / Player 快照都公开元素、姿态、两步序列、剩余窗口和当前反应，不让 HUD 读取私有字段。

## HUD 与反馈

- 复用现有 HUD 样式增加一个紧凑元素面板，不建立新的 UI 系统。
- 第一行显示姿态、元素和切换键；第二行显示两步序列、反应名和剩余秒数。
- 攻击 VFX 按当前元素着色：风为青绿，雷为蓝紫；判定仍以物理查询为准。

## 验收

1. Main 启动后存在元素 / 姿态切换输入，风印前只有雷，风印后可在风雷间循环。
2. 两种顺序产生不同判定或击退结果，窗口超时后序列清空。
3. 当前元素与姿态跨三个既有战斗房保持，序列在换房、失败与重开边界正确清理。
4. HUD 显示姿态、元素、序列和倒计时。
5. Stage3 / 6 / 10 / 13 / 15 / 17 / 20 邻近回归、Stage21 专项、全量 GUT、Godot import、主场景 smoke 与运行态复核通过。

## 非目标

- 不新增独立技能、法力、元素伤害数值或敌人抗性；敌人与 Boss 的专属反应属于 Stage22。
- 不新增位图资产、动画状态、元素槽位页面或通用连招框架。
- 不在 Stage21 解锁火、水、山、木、金或影元素。
