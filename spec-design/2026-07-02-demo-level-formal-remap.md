# Alpha Demo Formal Level Remap Design Direction

## 文档定位

本文档回应 2026-07-02 运行态复核中暴露的正式 Demo 关卡问题：红绿封印门和绿色台阶读值混乱、普通房间不能反向返回、房间连接处像落坑、房间尺度过短以及背景只能局部覆盖。

本轮不是 Stage17 玩法扩张，也不是商业版完整地图。目标是把当前 Alpha Demo 从“线性可通的原型房间链”升级为“符合正常横版类银河恶魔城直觉的正式 Demo 区域”。

## 设计结论

- 当前 `P0/P1/P2=0` 的自动报告不能单独证明关卡体验合理。它证明主线能通、资产有绑定、截图门禁通过，但不能证明房间连接、回退路径、危险区布置和强视觉元素读值符合玩家直觉。
- 红绿封印门不是台阶，但它的图形语言像可踩结构，必须替换为明确的封印门 / 结界 / 镇妖柱。
- `GoalLedge` 这类绿色纯色平台如果承担可站地形，必须替换为正式台阶或石台；如果只是目标提示，必须移出碰撞层。
- 普通横版银河城房间默认应双向通行。只有 Boss 锁门、剧情封锁、单向滑落或奖励捷径可以单向，并且必须有画面和 HUD 解释。
- 房间边界不能靠空白落坑完成切房。落坑应是房间内部挑战，且有明确危险视觉、回收路径或 checkpoint。
- 房间长度应由玩法节奏决定，背景用可延展层适配，不应为了单张背景而压缩房间。

## 目标

1. 生成正式 Demo 级地图拓扑：主线、支路、回溯、锁门和单向例外都有明确表。
2. 建立双向房间连接契约：普通相邻房具备左 / 右出口、反向 spawn 和安全落点。
3. 清理强视觉误读：封印门、目标点、台阶、危险区和出口不再使用纯色调试块作为主视觉。
4. 重排关键房间尺度：教程、目标房、Stage13 入口、Stage14 gate、Stage15 Boss 前、Stage16 threshold 等房间达到正式 Demo 节奏。
5. 建立背景延展规则：按远景 / 中景 / 近景层覆盖相机范围，不把背景画成可站地形。
6. 用 Godot MCP Pro 做阶段六运行态人工复核；图形缺口允许使用 image_gen 生成正式资产。

## 非目标

- 不新增完整小地图、传送系统、存档槽或商业版大地图。
- 不重做玩家移动、攻击、敌人 AI、Boss 状态机或 HUD 主系统。
- 不一次性手工清稿所有商业级 autotile。
- 不为单次修复引入额外 Godot 插件。
- 不把 image_gen 当作默认万能替换；现有资源能修好读值时优先复用。

## 正常横版类银河城关卡原则

### 房间拓扑

- 普通连接默认双向。
- 能力门应允许玩家看见“现在过不去，以后回来能过”的信息。
- 支路应在主线附近形成回路或奖励返回，不把玩家送进不可解释的死路。
- Boss 锁门必须在进入前给出竞技场感、门关闭反馈和失败回收点。

### 房间节奏

- 教程房：至少 3 个短段，分别验证移动 / 跳跃、冲刺、攻击 / 门控。
- 普通过渡房：约 1.5 到 2 屏，承担区域呼吸和方向确认。
- 机制房：约 2 到 3 屏，先展示、再验证、最后允许出房。
- 回溯 hub：至少 2 屏，能读出左右路径和回环关系。
- Boss 房：可短，但必须有清晰竞技场边界。

### 出入口安全

- 右出口进入下一房后，玩家必须落在稳定地面或明确平台上。
- 左出口返回上一房后，也必须落在稳定地面或明确平台上。
- 普通出入口附近不放无提示落坑。
- 真落坑只作为挑战段，必须具备危险视觉、回收路径、checkpoint 或伤害反馈。

### 视觉语义

- 红色 / 绿色 / 发光 / 符印等强视觉元素必须对应明确状态。
- 可站平台必须有厚度、边缘、材质和碰撞一致性。
- 不可站背景不能画成前景平台。
- 触发区提示只能是极弱辅助，不能成为主视觉。
- TileMap / Sprite2D 负责视觉，StaticBody2D / Area2D 负责碰撞和伤害；二者必须对齐。

## Image Gen 使用边界

允许 image_gen 的资产族：

- `formal_seal_gate`：关闭 / 可触发 / 已完成三态封印门或符印结界。
- `formal_goal_ledge`：正式可站石台、符印台阶、平台端头和中段。
- `formal_exit_marker`：门洞、雾门、符印光圈、区域转场牌。
- `parallax_shrine_layer`、`parallax_miasma_layer`、`parallax_seal_layer`：可横向延展的远 / 中 / 近景层。

禁止 image_gen 输出：

- 带英文、UI、角色、血条或 logo 的场景图。
- 无规则网格、不能切片的 tileset。
- 会被误认为可站平台的背景插画。
- 烘入碰撞、伤害边界或玩法提示的纯插画。

## Godot MCP Pro 阶段六使用边界

Godot MCP Pro 用于运行态证明，不代替设计判断：

- 启动主场景并从主菜单进入 Demo。
- 人工式输入验证左右双向切房。
- 截取关键房间入口、中心、出口和反向返回截图。
- 读取 collision、TileMap、scene tree 和相机边界。
- 结束后清理临时 autoload / project.godot 噪音。

## 完成口径

本轮完成必须同时满足：

- 正式计划、设计方向、实施清单和进度日志已落地。
- 普通相邻房间双向连接通过自动化测试和运行态抽样。
- 连接处无无提示落坑。
- 红绿封印门、绿色台阶和目标点不再误读为调试块。
- 至少 5 个样板房完成正式地形 / 背景 / 出口读值。
- Godot import、相关 GUT、full-flow 证据、输入式 replay 和 Godot MCP Pro 阶段六复核通过。
