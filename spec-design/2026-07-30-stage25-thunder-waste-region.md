# Stage25 雷泽荒原小型第二区域设计

## 目标

在镇妖驿厅完成三条悬赏后开放一片 6 房小区域，用现有风 / 雷两步序列验证“元素能力也能承担区域解谜”，并形成一次旧区回访与一次内部回环。

## 区域拓扑

| ID | 房间 | 作用 |
| --- | --- | --- |
| `35` | 荒原界碑 | 从 Stage11 进入的安全入口与 checkpoint |
| `36` | 雷雨洼地 | 首次展示雷暴危险 |
| `37` | 引雷坡道 | 回环汇合点 |
| `38` | 风蚀岔口 | 主路通往终点，可选上层支路通往继电器 |
| `39` | 接地祭柱 | 用“风→雷 · 追击贯穿”接地，解除雷暴并开门，随后回到 `37` |
| `40` | 驿路远眺 | 区域出口，返回 Stage11 镇妖驿厅 |

主路为 `35 → 36 → 37 → 38 → 40 → 11`；内部回环为 `38 → 39 → 37`。Stage11 到 `35` 的入口要求三条悬赏全部回交，奖励文案“雷泽荒原路引”因此成为真实门控。

## 主题机制

- **雷暴危险**：玩家首次触碰造成 1 点伤害；同一房间只结算一次，不建立持续 DOT 或天气状态机。
- **接地祭柱**：只响应 Stage21 已存在的 `wind_thunder_pierce` 反应；成功后关闭当前房间雷暴并解开出口。
- 继电器不复制玩家序列逻辑，不引入第三元素、元素抗性或通用机关框架。

## 表现与资产

- 灰盒复用现有瘴泽背景、正式地形材质、封印门与装备图标，通过冷蓝调和雷纹几何建立雷泽辨识度。
- 本阶段不新增图片、不把候选 source sheet 当成运行时资产。
- 地图 JSON 增加 `waste` 区域、6 个房间、两条远端连接，并继续由现有发现式地图动态绘制。

## 状态边界

- 悬赏回交状态继续由 Main 保存；Stage11 房间只读取快照决定入口是否可用。
- 雷暴是否结算、祭柱是否接地都只属于当前房间实例；切房后不写入存档。
- 世界图发现状态沿用既有 `visited_room_paths`，重开 Demo 时与悬赏状态一起清空。

## 验收

- 未取得路引时 Stage11 雷泽入口不可进入；三条悬赏全部回交后可进入 `35`。
- 6 个场景均可加载，主路、旧区返回和 `38 → 39 → 37` 回环可达。
- 雷暴造成一次伤害；错误元素 / 序列不能接地，正确序列关闭危险并开门。
- 世界图覆盖 44 个正式房间与 8 条远端连接，Stage19 发现式地图契约同步更新。

## 非目标

- 不做新敌人池、正式天气系统、雷元素伤害体系、区域 Boss、地图传送或正式存档。
- 不为 6 个房间分别创建脚本；场景差异仅由共享基类导出字段和节点摆放表达。
