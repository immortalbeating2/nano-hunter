# 北极星后续 Stage 路线设计

## 文档定位

本路线图基于当前 Stage20 分支候选：Alpha Demo 已具备 `38` 个正式房间、`3` 个区域环、`6` 条远端连接、发现式地图、风印、Air Dash、两件可切换 Build、一次剧情事件和全量自动化回归。

当前最大缺口不是继续增加房间，而是北极星独特核心仍未成型：元素序列连锁、符印姿态切换、驿站悬赏、圣物 / 组件成长和南北朝佛妖叙事尚未形成稳定生产循环。

## 当前完成度判断

| 北极星维度 | 当前状态 | 后续判断 |
| --- | --- | --- |
| Alpha 技术与关卡骨架 | 已达到较高可试玩基线 | 暂停大规模加房，先补核心玩法 |
| 银河城探索结构 | Stage18-20 已形成 Alpha 闭环 | 只在新系统需要验证时局部调整路线 |
| 元素 + 姿态 + 序列 | 只有风印能力雏形，无姿态和序列窗口 | Stage21 最高优先级 |
| 敌人与 Boss 互动 | Caster 有弹体，Boss 仍偏传统接触 / 形态测试 | Stage22 把元素序列压进战斗 |
| 驿站 / 悬赏 / 叙事 | Stage11 有一次事件，没有悬赏循环 | Stage23 做最小驿站闭环 |
| 成长 / Build / 圣物组件 | 只有两件单槽 Build | Stage24 扩到小型装备选择 |
| 区域与商业体量 | 现有区域仍少于北极星 6-8 区域 | Stage25 只做第二区域原型，不铺商业全量 |
| 发布级体验 | 自动化强，真人 / 手柄 / 存档仍不足 | Stage26 做候选收口 |

## 后续 Stage 总览

### Stage21：元素序列与符印姿态最小闭环

目标：让 Nano Hunter 第一次拥有“只有本项目才成立”的 30 秒战斗循环。

范围：

- 元素：先用 `wind` 风、`thunder` 雷两种。
- 姿态：先用 `疾` 和 `御` 两种。
- 序列：只记录最近两步元素事件。
- 组合：`wind -> thunder` 形成追击 / 贯穿型效果；`thunder -> wind` 形成击退 / 散射型效果。
- HUD：显示当前姿态、当前元素、两步序列和窗口倒计时。
- 输入：复用现有攻击 / dash / build 入口，新增最少必要按键；不得一次做 6-8 元素或 4-5 姿态。

退出标准：

- 玩家可以在三个既有战斗房里切换姿态、打出两种顺序不同的序列效果。
- 序列窗口超时会清空，换房和重开状态明确。
- Stage21 专项、邻近战斗回归、全量 GUT、Godot import 和运行态复核通过。

### Stage22：元素敌人与 Boss 反应切片

目标：证明元素序列不是 UI 装饰，而能改变敌人、危险和 Boss 的打法。

范围：

- Caster：加入可被 `thunder` 打断或被 `wind -> thunder` 反制强化的施法窗口。
- Charger：加入 `thunder -> wind` 击退 / 破势反馈。
- Seal Guardian：只加入一个元素反应窗口，不重做 Boss 全套阶段。
- 封印脉冲：允许一种元素序列短暂削弱或错开节奏。

退出标准：

- 至少三类敌对对象对元素序列有可观察差异。
- 战斗测试同时覆盖普通攻击、风印、两姿态、两序列和旧失败恢复。
- 不新增敌人类别，不扩大 Boss 阶段。

### Stage23：镇妖驿站与悬赏榜最小循环

目标：把北极星的“驿站接榜 -> 探索 -> 战斗 -> 回驿站兑换”做成最小可玩循环。

范围：

- Stage11 驿厅升级为可交互驿站。
- 悬赏榜提供 2-3 个固定悬赏：击败 Caster、回收妖骨证据、清理封印脉冲。
- 完成悬赏后返回驿站领取奖励或情报。
- 叙事只用现有详情面板和文本，不做对话树。

退出标准：

- 至少一个悬赏能从接取、追踪、完成、回交到奖励全程跑通。
- 悬赏状态进入 Main 快照，重开清空或按届时存档策略处理。
- 不实现随机任务、交易市集或 NPC 群像。

### Stage24：圣物 / 组件 Build 深化

目标：把当前两件 Build 从单按钮切换扩展为小型选择系统。

范围：

- 保留低膨胀数值，只做 2 个圣物槽。
- 新增 2-3 个大妖组件或佛门圣物，绑定已有 Boss / Caster / 隐藏路线。
- Build 影响元素恢复、序列窗口、姿态冷却或攻击范围中的少数维度。
- UI 使用暂停菜单轻量面板，不做完整背包。

退出标准：

- 至少 4 件可选 Build 中任意 2 件可装备。
- 装备选择对 Stage21 / 22 的核心战斗有实际影响。
- 存档策略若未正式实现，则明确仍为单次 Demo 会话状态。

### Stage25：第二区域原型与主题机制

目标：开始从单一 Alpha 区域走向北极星多区域，但只做一个小型新区域原型。

范围：

- 推荐区域：雷泽荒原。
- 房间规模：`6-8` 个，不追求完整商业区。
- 机制：雷元素、导电机关、雷暴危险或雷属性妖怪三选二。
- 路线：至少一个旧区回访口和一个新区域内小回环。
- 美术：允许灰盒 + 现有东方奇幻资产，不阻塞玩法。

退出标准：

- 新区域能证明第二元素 / 第二区域玩法差异。
- 旧地图 JSON、发现式地图和回访门控同步。
- 不同时开启火 / 水 / 山 / 木等全元素池。

### Stage26：北极星 Alpha Candidate 收口

目标：把 Stage21-25 整合成可交付的北极星 Alpha 候选。

范围：

- 连续试玩：首次通关、回访路线、悬赏回交、Build 调整、Boss 收束。
- 工具与体验：实体手柄、暂停 / 地图 / HUD、失败恢复、音效缺口清单。
- 最小存档策略：至少明确继续游戏、重开 Demo、当前进度边界。
- 文档：更新 release notes、QA checklist、北极星实现度复核。

退出标准：

- 真人首次通关和至少一次能力回访试玩通过。
- 全量自动化、Godot import、主场景 smoke、运行态截图 / 视频证据通过。
- 能说明哪些是 Alpha 候选已完成，哪些仍属于商业版扩展。

## 推荐顺序

1. Stage21 必须先做。没有元素姿态序列，后面所有内容仍只是普通银河城。
2. Stage22 紧跟 Stage21。核心玩法必须压到敌人和 Boss 身上，不能只停留在训练房。
3. Stage23 之后再做。悬赏循环需要已有战斗目标，否则只是菜单。
4. Stage24 依赖 Stage21 / 22。Build 必须服务元素序列，不应先扩装备页。
5. Stage25 等核心循环稳定后再开新区域。
6. Stage26 是候选收口，不新增大系统。

## 非目标

- 不把后续路线一次性扩成完整商业版。
- 不在 Stage21 前新增大批房间、敌人、美术或剧情分支。
- 不建立大型技能树、交易市集、通用对话编辑器或存档系统，除非对应 Stage 明确要求。
- 不把元素池一次做满；每个新元素都必须有战斗、探索和 UI 证据。
