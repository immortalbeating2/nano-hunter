# 右侧“符印共鸣盘”HUD 语义重构设计

Date: 2026-08-10

Type: 非 Stage 专项 UI 语义修复

Status: 已实现运行态技术候选，待真人视觉、来源授权与 Gate26H 签核

Self Review: 2026-08-11 已完成范围、现有运行契约与验收边界复核

## 目标

把右侧 `ElementPanel` 从“操作提示 + 调试状态文字”重构为 Luna 的战斗状态仪表“符印共鸣盘”。常驻 HUD 只回答当前元素、当前姿态和两步序列状态，不再显示 `Q 元素 / E 姿态`、固定秒数说明或教学句子。

该修复不改变 Stage21 的元素、姿态、序列窗口、攻击判定或输入映射；只重构信息层级、表现状态、教程归属与正式 UI 资产。

## 当前问题与原因

- Stage21 原型设计曾要求紧凑元素面板同时显示姿态、元素、切换键、序列、反应名与剩余秒数；`TutorialHUD._update_element_status()` 因此持续硬编码 `Q 元素 / E 姿态`。
- 该做法适合功能验证，却混合了两种职责：操作说明属于教程 / 控制设置，元素与序列属于战斗状态。
- 后续北极星已经要求玩家不依赖右上角文字也能识别风、雷、疾印、御印与两种序列结果；当前三行文字面板没有同步升级。
- 风元素在风印解锁前不可切换，开局常驻显示 `Q 元素` 还会暗示一个并不存在的选择。

## 已批准定位

右侧 HUD 的正式名称为“符印共鸣盘”。它不是传统技能栏，也不展示按键、招式列表、冷却数字或教程说明。

它持续回答三个问题：

1. Luna 当前以哪一种元素驱动符印：风或雷。
2. Luna 当前以哪一种施力法运转符印：疾印或御印。
3. 最近两次元素攻击形成了怎样的灵力链：空、第一步蓄印、两步反应。

## 信息架构

### 常驻信息

- 当前元素：以独立元素印记为主，保留一个汉字标签作为辅助。
  - 风：青绿色旋流 / 羽状外旋轮廓。
  - 雷：蓝紫色分叉 / 震纹轮廓。
- 当前姿态：以独立结构轮廓为主，保留一个汉字标签作为辅助。
  - 疾印：外张、偏斜、具有前冲方向的开式印纹。
  - 御印：闭合、同心、具有护轮结构的守式印纹。
- 常态不显示序列空文案；不得出现 `序列：—`。

### 条件信息

- 第一次元素攻击后显示第一枚序列印和一个待填充印槽。
- 第二次攻击后点亮第二枚印，通过灵力链连接两者。
- 形成反应时短暂显示 `追击贯穿` 或 `散射破势`；反应名称属于结果反馈，不是教程文本。
- 默认不显示 `1.4s` 一类数字倒计时。剩余窗口通过灵力链缩短、符环退色或墨迹消散表达。
- “显示序列数字计时”可作为后续可访问性候选，但不属于本轮修复范围；本轮不新增设置项，也不改变玩法计时。

## 显示状态

| HUD 状态 | 进入条件 | 主要内容 | 退出条件 |
| --- | --- | --- | --- |
| `idle` | 序列为空 | 当前姿态印 + 当前元素印 | 第一次攻击记录元素 |
| `primed` | 序列含一个元素 | 当前双印 + 第一序列印 + 空印槽 + 衰减灵力链 | 第二次攻击或窗口耗尽 |
| `resolved` | 序列含两个元素并有反应 | 两枚序列印 + 反应轮廓 + 短暂反应名 | 下一次攻击滚动序列或窗口耗尽 |
| `switch_feedback` | 元素或姿态 ID 发生变化 | 对应印记短促翻转 / 盖印反馈 | `0.18–0.28s` 后回到其基础状态 |

`switch_feedback` 是展示叠加态，不新增 Player 状态，也不改变 `0.35s` 姿态切换冷却。

## 布局与占屏

- 保持右上角定位，与左侧 BattlePanel 和顶部 PromptPanel 避让规则不变。
- 常态逻辑尺寸为 `232x116`：横向占比收拢，主元素印控件为 `60x60`、姿态卫星印控件为 `36x36`。
- `primed` / `resolved` 使用 `324x156` 的展开尺寸；主元素印 `62x62`、姿态印 `38x38`、序列印各 `29x29`、反应终点 `34x34`。旧 `80/52/36/36/48` 与随后 `72/44/30/30/40` 只约束 Control 外框，不能证明真实 Alpha 图案居中或不过圈，均已由 2026-08-12 方案 A keyline 合同取代。
- 常态与展开态各使用一张按最终比例生成的完整 Image Gen 框体，整张切换；不得使用 NinePatch 拉伸官印、链路、挂件或印槽。
- 内容层顺序固定为：动态符印 / 标签 > 完整 FrameArt > 透明内容安全区 StyleBox > 游戏世界。
- 右侧官印、顶轨与朱砂印继续遵守 `02 镇妖官印`，但内容区必须为两种状态留出明确的印槽结构，不得再像通用文本框。

## 操作提示迁移

### `E` 姿态

- 放入初始战斗教学，位于基础攻击教学之后、离开教程房之前。
- PromptPanel 只在该教学步骤显示当前设备的实际绑定，例如键盘 `E` 或手柄对应图标。
- 玩家完成一次姿态切换后结束提示；之后不在常驻 HUD 重复。

### `Q` 元素

- 风印解锁前只有雷元素，不能提前提示 `Q` 存在可切换选择。
- 风印首次解锁并自动切换到风时，由 PromptPanel 显示一次上下文教学，要求玩家完成一次风 / 雷切换。
- 控制说明与设置页始终列出元素切换和姿态切换，并读取真实 InputMap / 手柄绑定，不写死 `Q/E`。

## 世界观与角色对应

- 外框黑漆木、旧铜与官印表达 Luna 的公开身份：皇家镇妖卫体系中的赏金猎人。
- 内部佛门符印、同心法轮和灵力链表达她习得的佛门符印法。
- 风 / 雷能量被限制在印槽与链路内，表现她用符印约束妖性吸收来的元素，而不是普通法师技能栏。
- 妖性异色、裂纹或不稳定脉动只在妖性吸收 / 觉醒相关状态出现；常态不得把 Luna 直接表现成失控妖物。
- 风、雷、疾、御必须同时依靠轮廓、方向、颜色和短动画区分，不能只换色或只换汉字。

## 动效

- 常态不做持续高频呼吸，避免右上角长期抢夺战斗注意力。
- 元素切换使用短促流光换轨；姿态切换使用开式 / 闭式印纹转换；两者不共用同一动画。
- 第一步序列只点亮一枚印并启动衰减链；第二步反应才允许一次明确亮闪与反应轮廓。
- `追击贯穿` 使用向前贯穿的水平线势；`散射破势` 使用向外张开的放射线势，不只改变文字。
- reduced-motion 开启后取消位移、旋转和连续流动，只保留瞬时换图、颜色和透明度变化。

## 资产方案

第 1 轮 v1 因装饰密度过高、实机语义符号不可读而被真人否决。第 2 轮以用户选定的 Option 02 设计稿和真实 gameplay 为冻结参考，通过官方 Image Gen 重新生成，不用程序化 SVG 或概念图裁切代替美术：

- `hud_seal_resonance_v2/seal_resonance_idle_frame_warden_ai02.png`：闭合官印完整框体，`928x464`，可见轮廓约 `1.887:1`。
- `hud_seal_resonance_v2/seal_resonance_active_frame_warden_ai02.png`：带实体折叠铰链的 L 形展开框体，`1296x624`，可见轮廓约 `2.125:1`。
- `hud_seal_resonance_v2/seal_resonance_symbols_warden_ai02.png`：`768x512` 的 3x2 atlas；风、雷、疾、御、贯穿、散射各占独立 `256x256` region，并统一 `60px` 光学半径。

所有运行 PNG 必须有 Alpha、透明四角、来源旁置记录、候选 / 输出 SHA256 和人工发布边界。两张框体必须整张等比显示；六枚符号须先按统一 Alpha 质心与光学半径规范化，再以固定方形槽位等比显示，不能把 `TextureRect` 中心或最远尖端当成图案视觉大小。

## 数据与实现边界

- 继续读取 Player 已公开的 `current_element_id/label`、`current_stance_id/label` 和 `element_sequence` 快照。
- HUD 可保存上一次元素 / 姿态 ID 以触发切换动画，但不得读取 Player 私有字段或反向写入战斗状态。
- 不增加新的序列计时器；视觉衰减只能读取现有 `window_remaining / window_duration`。
- 为降低改动面，运行节点名可继续保留 `ElementPanel`，新增 `metadata/hud_role="seal_resonance"`；面向玩家和文档统一称“符印共鸣盘”。
- 不新增第三元素、新姿态、技能槽、法力、异常状态或通用 HUD 框架。

## 实现结果（2026-08-11）

- 用户已选定 Option 02 为唯一视觉真值；冻结稿为 `selected_option_02_command_seal_sha256_941695354052e8fd.png`，SHA256 `941695354052e8fdfe561136c36a7441d53e870d7d73257da9eb7b0dd2e07241`。v1 保留为被否决的历史资产，不再是生产消费者。
- v2 资产分别生成闭合框、展开框与六符号图集。展开框首稿因上下两段存在绿色间隙、仍像粘贴组件而被内部 QA 拒收；终稿增加一枚真实触碰上下框体的宽铰链，消除该 P1 结构问题。
- `SealResonanceHud` 已接入生产 `ElementPanel`，按现有 Player HUD 快照呈现 `idle / primed / resolved` 三态；常态与展开态使用两张完整等比 FrameArt，六枚固定 AtlasTexture 表达风、雷、疾、御、风雷贯穿与雷风散射，灵力链只读取现有序列窗口。
- 初始教程已迁移为五步 `move_jump -> dash -> attack -> stance -> exit`，姿态步骤读取真实 InputMap 的 `E / RB / R1`；元素提示只在风印首次解锁后以 `Q / LB / L1` 上下文教学出现，完成一次真实元素切换后恢复最新房间提示。Controls / Settings 同样从真实 InputMap 生成文案。
- v2 真实窗口证据为 `34` 张 full 与对应 crop：7 档布局、5 种语义状态、8 帧反馈、10 个五步教程双设备画面、3 个风印上下文画面，以及 1 张与选稿同为 `1672x941`、同为风→雷贯穿状态的设计 QA 画面。它们只证明 runtime technical candidate，不是人审通过。
- v1 历史 generation input 的恢复证据仍保留，但不再作为 v2 生产事实。v2 只引用本轮冻结的 Option 02 选稿与 `1280x720` gameplay 上下文副本；专项 strict 会复算路径、尺寸、字节数与 SHA256。
- 2026-08-11 收口回归为 Stage16 `22/22` tests、`606` assertions；递归 GUT `53` scripts、`365/365` tests、`10750` assertions，均 exit `0`。Stage12、Stage26、import 与递归 GUT 保留 ObjectDB leak warning，Stage21 保留既有 orphan 输出；没有解析或失败断言。
- 当前状态仍为 `runtime technical candidate`；三项 v2 HUD 资产保持 `runtime_binding_allowed=true`、`final_ready=false`。真人视觉、物理阅读距离、动效强度、来源 / 授权和 Gate26H 均未签核，没有 commit、push 或 release。

## 2026-08-12 五语义锚点纠偏

用户对 v2 实机复核后确认：框体美术方向可以保留，但动态符号没有落在美术预留圆框中。旧自动门槛只检查资源路径、控件尺寸、面板不越屏与全局矩形安全区，因此把明显错槽误判为 `ok=true`；该结论作废。

本轮把展开态五个圆框正式命名为 `element / stance / sequence_a / sequence_b / reaction`，idle 只启用前两个。锚点坐标以最终 FrameArt 原生像素测量后按 `0.25` 映射到逻辑坐标，运行脚本必须按圆心居中，不再把手写的左上角位置当成视觉事实。

正式门槛如下：静态圆心误差不超过 `2px`；符号包围盒必须完整位于对应槽位；元素 / 姿态动效只能在本槽的允许包络内；三组辅助文字各自位于命名安全区；灵力链只能占用两个序列槽之间的连接走廊。真实窗口报告必须逐项输出误差并让错槽、越界或连接带覆盖槽位直接使总结果失败。

本轮视觉真值补充为 `user_selected_semantic_anchor_target_sha256_3d25aee0f20cd7a7.png`，SHA256 `3d25aee0f20cd7a7302962b1444f88ec2620cce19ac4b1b72183e29fc0f6268f`、尺寸 `1672x941`。它用于层级、语义和同状态对照，不替代 v2 两张完整 FrameArt，也不授权重做其它 HUD。

新的机器几何 PASS 只说明五个动态图层正确落槽；最终美术、物理阅读距离、动效强度、授权和 Gate26H 仍需真人签核。

执行结果：五个静态圆心的报告误差均为 `0px`，反馈期间最大实际误差为 `3.898438px`，仍在元素换轨 `4.01px` 包络内；全部 `34` 张真实窗口捕获的槽位、文字区与连接带 gate 通过。首个居中版本因 `80/52/36/36/48` 符号挤压金属内圈被目检拒收，最终采用 `72/44/30/30/40`。这不改变参考稿与当前 FrameArt 在开放式紫雷轮廓、L 形闭合结构和色彩语言上的差异；若用户要求形态也一致，应另开 FrameArt 生成 / 接入轮次，不能把本轮几何 PASS 写成完整美术还原。

## 2026-08-12 方案 A：统一 Keyline 与最终像素门禁

用户进一步指出：即使 Control 圆心和最远径向 keyline 正确，细长“贯穿”仍会在更大的反应圆里显得最小。方案 A 最终以 `Alpha>=16` 权重质心统一到 `(128,128)`，再用 95% Alpha 分布半径与等效墨量复合得到光学半径；六枚目标 `60px`、允许 `57–63px`，最远核心 `<=104px`。相同 `29px` 圆框的序列印应等大，`34px` 反应印应接近 `34/29` 倍；最终实机仍要求圆内核心余量 `>=2px`、越界核心像素为 `0`。

五个运行槽位改为真实内圆直径：idle `60/36px`，active `62/38/29/29/34px`。圆形安全 Shader 必须用当前 AtlasTexture 的 `region_uv_rect` 先把 atlas 全局 UV 还原为单格局部 UV；否则不同 region 会被非对称裁切。元素反馈只允许围绕圆心的 `0.94 → 1.03 → 1.0` 缩放与透明度变化，不再允许 `+4px` 位移。

历史首轮机器结果曾只证明六枚最大半径与径向填充接近；用户复核证明这不能代表光学大小。2026-08-12 二次纠偏后，六枚源图光学半径统一为 `59.944261–59.977866px`，最大核心半径仅作为 `<=104px` 防越界安全线；44 张真实窗口捕获包含 10 组 glyph-only 像素证据，同尺寸序列图标光学比为 `0.9791–1.0214`，34px 反应图在 1x 及以上为 29px 序列均值的 `1.1365–1.1894`，越出安全圆的核心像素总数 `0`。这些数据只形成运行技术候选，用户对新实机图的视觉签核、来源 / 授权和 Gate26H 仍开放。

## 验收

1. 常驻右侧 HUD 不包含 `Q`、`E`、`元素切换`、`姿态切换`、`序列：—`或固定按键说明。
2. `idle`、`primed`、`resolved` 三态分别绑定正确完整框体和动态符号，且不存在 gameplay `OrnamentLayer`。
3. 当前元素与姿态可在无按键文字条件下通过形状、颜色和辅助标签辨认。
4. 风印解锁前不显示虚假的元素切换提示；解锁后 PromptPanel 才出现一次上下文教学。
5. 两种序列顺序具有不同连接轮廓和短暂结果反馈；没有数字计时时仍可理解窗口正在衰减。
6. 七档支持视口中右侧 HUD 位于安全区、不与 Battle / Prompt 重叠，文字和符号不触碰框体。
7. reduced-motion、键鼠 / 手柄提示、Controls / Settings、Stage21 专项、HUD 回归、严格资产审计、Godot import、真实窗口截图和递归 GUT 全部取得新鲜证据。
8. 自动结果只形成技术候选；最终角色契合度、阅读距离、动画强度和 Gate26H 仍由真人签核。

## 非目标

- 不删除元素 / 姿态 / 序列系统。
- 不把右侧 HUD 改成六元素技能轮盘、快捷栏或装备栏。
- 不在本轮重做 Battle、Prompt、Pause、Failure 或主菜单。
- 不因移除按键文字而减少控制说明、重绑定或无障碍信息。
- 不在本轮新增数字倒计时开关或扩展 Settings 信息架构。
